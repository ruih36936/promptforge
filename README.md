# ⚒ PromptForge · 提示词锻造炉

> 把一句话，锻造成 AI 能一次做对的指令。

一个**纯前端、零依赖、不需要服务器**的提示词优化工具。输入你随口说的需求，输出一段结构完整、约束明确、带自检清单的提示词，直接粘给 ChatGPT / Claude / DeepSeek / Kimi / 豆包。

打开就能用：不用注册、不用 API Key、不上传任何数据。

---

## 这是什么

大多数人写提示词的方式是：`帮我写个小红书文案`。

模型收到这句话，只能靠猜：给谁看、多长、什么语气、什么算写得好。猜错的地方，就是你反复追问、反复重写的地方。

PromptForge 做的事只有一件：**把这个猜测的过程变成填空**。

它会自动补齐模型最容易搞错的六样东西：

| 补什么 | 不补会怎样 | 补完怎样 |
| --- | --- | --- |
| **角色**（它是谁） | 输出风格飘忽，一会儿正经一会儿网感 | 视角固定，专业度稳定 |
| **背景**（给谁、为什么） | 编造受众和场景，写得很对但没用 | 内容真正落到你的场景 |
| **硬约束**（什么算不合格） | 写了 2000 字你想删到 300 字 | 一次到位，少返工 |
| **输出格式**（交付形状） | 你还要再来一轮「按表格重排」 | 直接能贴进文档 |
| **自检清单**（交卷前核对） | 第一版总有明显毛病 | 模型先自己改一遍 |
| **反编造条款** | 一本正经编数据、编出处 | 不确定就说不确定 |

## 怎么用（三步）

1. **左边写原话。** 用你平时说话的方式写，不用管格式。「帮手写个台灯的小红书笔记」完全可以。
2. **点「⚒ 锻造提示词」。** 右边出成品。带 `（待填写）` 的地方，是你还没说清的关键信息。
3. **补齐、复制、粘贴。** 切到「源码」可以直接改，改完自动同步。补齐 `（待填写）` 后复制，效果差别很大。

小技巧：

- **Ctrl / ⌘ + Enter** 直接锻造
- 不确定选什么类型，就选「自动识别」（没认出来会明说，不会假装认出来了）
- 送给 Claude 时选 Claude，它会自动改写成 XML 标签结构
- 用 o 系列 / DeepSeek R1 这类**推理模型**时选「推理模型」——这类模型自己会思考，多余的「先复述再展开」反而会带偏
- 嫌提示词太长就勾「**精简版**」：字数降约三分之一，适合小模型和短对话
- 勾「**加格式示例**」会给每种任务附一段输出骨架（只教结构，不提供可抄的内容）；你手上正好有满意的一例，就贴进下面的框里，会优先用你的——这比任何内置模板都准

## AI 增强（可选，需自备 Key）

不想只靠规则？展开面板填自己的 API Key，让模型把槽位补具体。

- **它只做一件事**：补全槽位 + 给 2–4 条场景化约束。提示词结构仍由规则引擎决定——模型跑偏也毁不掉骨架，最坏情况只是补错内容，你改一行就行。
- **实测浏览器能直连**：DeepSeek、硅基流动、阿里百炼（兼容模式）、Kimi / Moonshot、Claude。智谱 BigModel 和本地 Ollama 会被浏览器拦（CORS / 混合内容），请用「自定义」填自己的中转地址。
- **Key 只存在你这台电脑的浏览器里**，只发给你选的服务商，不经过任何中间服务器。但同页面脚本能读到它，**请用低额度 Key**，别放能刷爆的那种。
- **失败必回落**：没 Key、Key 错、超时、模型不按 JSON 返回——全部自动回落到纯规则引擎，功能不降级，只是槽位留空。
- 每次锻造大约花 1–2 千 token。

## 它为什么能提高命中率

不是玄学，是四条具体机制：

1. **角色锚定** — 明确「你是 12 年经验的内容策划」，比「你是助手」输出质量稳定得多。
2. **把要求变成可检查的条款** — 「别写废话」模型听不懂；「单段不超过 4 行、禁用『赋能/闭环』」它听得懂。
3. **约定交付形状** — 提前说清结构，省掉「你再按这个格式重排一遍」那一轮。
4. **输出前自检** — 让模型交卷前逐条核对、不合格自己重写。这一条对「一次就过」的提升最明显。

工具的评分条（原始 → 锻造后）是**结构完整度**，不是「质量分」。它衡量的是：模型还要猜多少。

## 部署说明（已经配好，不用再动）

线上地址：**https://ruih36936.github.io/promptforge/**

GitHub Pages 发布的是 `gh-pages` 分支。仓库里带了 `.github/workflows/deploy.yml`：每次 push 到 `main`，会自动把内容同步到 `gh-pages`，大约 1 分钟线上更新。

所以日常只有一件事：

```bash
git add -A && git commit -m "改了什么" && git push
```

> **每次改动后，把 `index.html` 里两处 `?v=4` 的数字 +1**（改成 `?v=5`）。
> GitHub Pages 的静态资源会缓存 10 分钟，不升版本号的话，你自己或朋友会看到旧版，误以为没改成功。

### 如果你 fork 一份自己用

1. 仓库 → **Settings** → 左侧 **Pages**
2. **Source** 选 `Deploy from a branch`，分支选 `gh-pages`，目录 `/ (root)`，Save
3. 推一次 `main`（工作流会把内容同步到 `gh-pages`），等 1–2 分钟
4. 地址变成 `https://<你的用户名>.github.io/promptforge/`

> 首次部署时 `gh-pages` 分支要存在，Pages 才会自动出现在设置里；本仓库已经有了。

## 想改？三个地方就够

全部集中在 `assets/app.js` 开头的第 1 节：

| 想做什么 | 改哪里 |
| --- | --- |
| 加一个业务场景（比如「法律意见书」） | `TYPES` 里加一条：角色、槽位、硬约束、输出格式、自检清单 |
| 加一个常用模板 | `TEMPLATES` 里加一行（图标、名字、属于哪个类型、原始提示词） |
| 支持新模型 | `MODELS` 里加一条；需要标签结构的用 `style: 'xml'` |
| 补自己的仓库地址到页脚 | 顶部 `REPO_URL` 填上，页脚 GitHub 链接自动生效 |

不需要懂框架，照着现有条目的格式抄一条即可。

## 边界（它不做什么）

- ❌ 不生成内容本身，只生成「给 AI 的说明书」
- ❌ 不联网、不调用任何 API、不消耗 token
- ❌ 不存储你的输入到任何服务器（只在你自己浏览器的 localStorage 里留最后一次）
- ❌ 不保证模型一定听话——但它把「不听话」的概率压低了
